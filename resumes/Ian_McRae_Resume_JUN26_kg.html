What is a Knowledge Graph, and why do AI agents use them?

🔗

Entities & Relationships

A knowledge graph stores information as nodes (entities: people, companies, products, concepts) and edges (relationships: "works at", "built", "skilled in"). Unlike a table row, every entity is richly connected.

🗺️

Traversal Over Lookup

Agents can traverse a KG to answer multi-hop questions: "which products did Ian build that touch healthcare?" requires following paths, not matching keywords. The graph is a map, not an index.

⚡

Structured Context for LLMs

LLMs reason better with structured context. Injecting a KG subgraph into a prompt (e.g., all nodes within 2 hops of "Amazon Connect") gives the model the precise relational facts it needs — no hallucination, no drift.

// Three triples from Ian's knowledge graph
ian_mcrae —[works_at]→ aws_applied_ai_solutions
aws_applied_ai_solutions —[builds]→ amazon_connect
ian_mcrae —[pioneered]→ knowledge_as_code

// Agent query: "What has Ian built that uses graph technology?"
MATCH (ian)-[:built|:owns]->(p)-[:built_on]->(knowledge_graphs)
RETURN p.label
// → semantic_data_layer, ragnet, knowledge_as_code
